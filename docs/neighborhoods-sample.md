# Neighborhoods — what the data layer actually produces

Generated by `cargo run --release -p polis-repo --example neighborhoods -- <repo> --markdown`.
Everything below is derived from the repository on this machine and nothing else:
no model, local or remote, was involved, and nothing left the box (PRD §2).

Three things are being shown at once, and they are the three decisions this round
implements.

**Kind (decision 2).** Every file gets a [`CodeKind`] — `source`, `test`, `docs`,
`config`, `build`, `assets`, `data`, `vendored`, `unknown` — from its path, and a
neighborhood's kind is the dominant kind of its files. This is what hue is meant
to encode: the `kind` column is the colour the map should be drawing. PRD §8's
industrial zone *is* `vendored`, decided by the existing `IndustrialRules` rather
than by a second list.

**Granularity (decision 3).** A district used to be a top-level directory. Now the
depth is chosen per branch: descend while a directory holds more than 8 % of the
repository, stop when a child would hold fewer than the floor. The
`top-level → neighborhoods` figure on each section is the before and after, and
`every directory would be N` is the other end of the range — the granularity
`polis-layout` already places plots at, which is far too fine to label.

**Description (decision 4).** Derived from a README in the directory, a package
manifest, a module doc comment, or — failing all three — a synthesised
*inventory* of what is actually there. The `source` column says which. Only the
first three are prose a human wrote, and the **prose** figure is the honest
coverage number; an inventory is always available and therefore proves nothing.

Empty means empty. A neighborhood with nothing true to say about it gets no
description, because a wrong or generic one is worse than none.

## Reading this honestly

**The kinds are good.** This is the part that works. `source` / `test` / `docs` /
`vendored` come out right on every repository tested, including the ones with
awkward conventions, and the two failures found by eyeballing were both fixed by
looking: `.vim` and `.scm` were `unknown` on Neovim (1 819 files — now `source`),
and Django's ten `contrib` apps read as `data` because 2 456 `.po` translation
files outvoted the Python. The second one is why a directory is now also split
when a child would be a **different colour**, not only when it is too big — the
`*/locale` rows in the Django table are that rule firing, and `contrib/admin`
reads `source` again beneath them.

Two known false positives, both left in on purpose and both fixable in one line
of `.polis/neighborhoods.json`: Django ships a `django/test/` package that is
production source and is classified `test`, and a `.po` catalogue is `data` even
though a translator would call it source.

**The granularity is good.** 3 → 68 neighborhoods, derived from the shape of each
repository rather than from a target count. The degenerate cases behave: a
17-file repository under 2 416 vendored files gets three neighborhoods and not a
pretend twenty; a chain of single-child directories collapses to one name.

**The descriptions are the weak half, and the number to look at is the prose
column, not the described column.** On this repository it is 79 %, because every
crate has a `//!` module doc and a `Cargo.toml` description. On the operator's own
repositories it is 19–31 %, and on Django 15 %. That is not a bug in the
extractor; it is a fact about the repositories. Directories in a working
application do not usually carry READMEs, and a codebase that documents itself at
the module level is the exception.

So the realistic outcome on the repositories this was built for is: **about a
third of neighborhoods carry a real sentence, and it is a good sentence when it
is there.** `Centralized Window Management Service`, `Firebase Cloud Functions`,
`This directory contains Vim scripts for syntax highlighting` — those earn their
place on a map.

The rest fall back to an inventory line, and those are worth judging separately.
`most imported: BookContext.tsx` is a fact the map does not otherwise show and
the name does not carry; it says *this is the neighborhood BookContext lives in*,
which is real wayfinding. `67 files named cover` says something true about a
directory of book covers. But they are inventory, not intent, and they should
probably be drawn differently — smaller, dimmer, or only at the district zoom —
so a person is never misled into reading one as a summary of purpose. The data
layer marks them (`DescriptionSource::Inventory`, `Description::is_prose`) so the
renderer can make that choice rather than having it made for it.

What was deliberately **not** done: no filler. `utils` is not described as
"Utility functions". A neighborhood with no README, no manifest, no doc comment,
no monument and no repeated filename gets `None`, and 13–38 of them do on these
repositories. That is the design working, not a gap.

## Safety

Every candidate description passes `describe::sanitise` before it can be stored,
because these end up drawn onto an image the operator may share:

* Markdown images are deleted whole, links keep their text and lose their URL,
  and HTML tags, `#`, `*`, backticks and pipes are stripped.
* Every C0/C1 control character is removed, and so are the Unicode bidi overrides
  and zero-width characters (`U+200B`–`U+200F`, `U+202A`–`U+202E`,
  `U+2066`–`U+2069`, `U+FEFF`) — text that renders as something other than its
  bytes is a spoofing channel on a shared picture, not a typographic nicety.
* A candidate is **rejected whole**, and the next source tried, if it reads as
  code (braces, `;`, `=>`, a leading `fn`/`def`/`$ `, a bare file path, or fewer
  than 70 % letters), or if it carries anything credential-shaped: a known key
  prefix (`sk-`, `ghp_`, `AKIA`, `AIza`, `eyJ`, `-----BEGIN`, …), an assignment
  to a name like `api_key`, a URL with a password in it, or a 20-character
  high-entropy token. Rejection rather than redaction, because a redacted secret
  still says *there is a secret in this file*.
* The result is bounded to 70 characters for the map label and 240 for the
  detail panel, cut at a word boundary and never inside a multi-byte character.

The counters are reported per repository above (`Rejected N candidates`). Across
all seven, 12 candidates were rejected: 9 as code or file paths, 3 as too short,
0 as credential-shaped.
